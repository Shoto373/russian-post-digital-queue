# Архитектурная спецификация: Управление сменой, аналитика загруженности, гибкая политика очередей и авто-скрытие ошибок

**Дата:** 19 сентября 2026  
**Статус:** Утверждено  

## 1. Контекст и цели
В ходе эксплуатации цифровой электронной очереди выявлен ряд критических требований к операционной надежности и удобству пользователей:
1. Ошибки интерфейса (включая Internal Server Error) не должны зависать на экране навсегда — требуется авто-скрытие и кнопка закрытия.
2. График загруженности отделения должен отражать реальную историю талонов отделения из базы данных и текущий наплыв посетителей, сглаженный эталонной моделью Почты России при малом объеме статистики.
3. Процесс завершения смены отделения: при закрытии смены операторы должны беспрепятственно завершить обслуживание текущих клиентов (`SERVING`, `CALLED`), а оставшиеся невызванные талоны (`WAITING`, `SCHEDULED`) автоматически отменяются с фиксацией причины закрытия смены.
4. Начальник отделения (ОПС) должен иметь возможность гибко задавать рабочий график отделения (будни, суббота, воскресенье, перерыв) и оперативно управлять сменой («Открыть смену», «Плавное закрытие», «Завершить смену»).
5. Конфигуратор весов очереди (`QueuePolicyEditor`) должен быть интуитивно понятным: начальник ОПС оперирует человекопонятными уровнями («Низкий», «Средний», «Высокий») и готовыми сценариями (пресетами), а сложные формулы скрыты в экспертный режим.

## 2. Архитектура подсистем

### 2.1. Автоматическое скрытие и закрытие ошибок (Frontend UX)
- В `ClientWorkspace.tsx` и модальных окнах добавляется хук/эффект:
  - Автоматическое скрытие ошибки через 6 секунд (`setTimeout`).
  - Кнопка ручного закрытия `[✕]`.
  - Плавное визуальное оформление баннера.

### 2.2. Сервис исторической загруженности отделения
- **Эндпоинт:** `GET /api/v1/branches/{branchId}/workload`
- **Логика бэкенда:**
  - Извлекает из таблицы `tickets` агрегированные данные по часам (8..21) за последние 30 дней для текущего дня недели.
  - Извлекает текущее количество талонов в статусе `WAITING` для калибровки текущего часа.
  - Вычисляет процент загрузки каждого часа и расчётное время ожидания (минуты).
  - Применяет взвешивание с эталонным профилем Почты России (Bayesian smoothing) для защиты от недостатка выборки (cold start).
- **Фронтенд:**
  - `BranchWorkloadCard.tsx` обращается к API загруженности отделения при монтировании и отображает живые почасовые столбики.

### 2.3. Жизненный цикл завершения смены (Shift Closure)
- **Эндпоинт:** `POST /api/v1/admin/branches/{branchId}/close-shift`
- **Процедура:**
  1. Окна отделения (`windows`) переводятся в статус `CLOSING` (или `CLOSED` если окно свободно).
  2. Новые вызовы талонов (`CallNext`) блокируются с ошибкой `WINDOW_CLOSED`.
  3. Клиенты в процессе обслуживания (`SERVING` или `CALLED`) остаются на своих окнах: операторы вызывают `CompleteService`, который завершает обслуживание штатно.
  4. Все оставшиеся в отделении невызванные талоны (`WAITING`, `SCHEDULED`) переводятся в статус `CANCELLED`.
  5. В таблицу `ticket_events` записывается событие `TicketEventCancelled` с `from_status` (`WAITING` или `SCHEDULED`) и системной причиной завершения смены.

### 2.4. Управление режимом работы отделения
- **Эндпоинты:**
  - `GET /api/v1/admin/branches/{branchId}/schedule` — получить расписание и текущий статус смены.
  - `PUT /api/v1/admin/branches/{branchId}/schedule` — обновить рабочие часы (будни, Сб, Вс, перерыв).
- **Хранение в БД:**
  - Таблица `branches` расширяется полями расписания или обновляется структурированное поле `work_hours`.
- **Фронтенд:**
  - Новая вкладка «Режим работы ОПС» в `AdminWorkspace.tsx`:
    - Редактирование часов работы по категориям дней недели.
    - Кнопки управления сменой: «Открыть смену», «Плавное завершение (дообслужить)», «Закрыть смену».

### 2.5. Дружелюбный конфигуратор весов очереди
- В `QueuePolicyEditor.tsx`:
  - 3 готовых пресета:
    1. **Баланс (Стандарт Почты России)**: W_apt=100, W_qr=10, W_live=10, порог=15м, льгота=15м.
    2. **Час пик (Борьба с очередями)**: W_apt=80, W_qr=20, W_live=20, порог=10м, льгота=10м, ускоренное нарастание.
    3. **Приоритет онлайн-записи**: W_apt=250, W_qr=10, W_live=10, порог=20м, льгота=15м.
  - Селекторы «Низкий» / «Средний» / «Высокий» для ключевых параметров:
    - Приоритет записи
    - Защита от долгого ожидания (Starvation Guard)
    - Льготный период
    - Строгость к опозданиям
  - Сворачиваемый блок «Экспертная настройка формул» (по умолчанию скрыт).
